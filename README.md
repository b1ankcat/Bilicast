# Bilicast

一个给 B 站用的后台播放器扩展。

`Bilicast` 不是收藏夹增强，也不是另一个稍后再看。它做的事情更直接：把 B 站视频里的音频部分抽出来，交给一套独立的播放列表和播放器控制来处理。

适合的场景也很明确：

- 听歌
- 听 Live / 演唱会 / 纯享
- 听播客、杂谈、知识区长视频
- 一边工作一边把 B 站当声音来源挂着

## 这个项目解决什么问题

B 站原生的收藏夹、稍后再看、list 更偏向“连续看视频”，不太像一个真正顺手的播放器。

如果你的需求是“听”，原生体验会有几个明显问题：

- 想顺着播一组内容，通常要先建收藏夹或者整理 list
- 自动切集、播完暂停这些逻辑跟页面播放器绑得比较紧
- 想切歌、循环、调音量，控制不够直接
- 很多时候只是想先加进去后台播，不想专门维护一个收藏夹

`Bilicast` 就是把“收集内容”和“控制播放”单独拆出来，按播放器的思路重新做一遍。

## 核心思路

`Bilicast = B 站内容源 + 自定义播放列表 + 独立后台播放`

重点不是“存起来”，而是“马上能听”。

所以它的设计取向很明确：

- 视频页就能一键加入
- 不要求先建 B 站收藏夹
- 播放逻辑独立于当前页面
- 切歌、循环、音量这些控制单独可用

## 和 B 站原生 list 的区别

最实际的区别有三点：

### 1. 它是播放器，不是列表附属功能

你可以直接控制：

- 播放 / 暂停
- 上一首 / 下一首
- 进度拖动
- 音量
- 播放模式

原生 list 还是围着页面播放器转，`Bilicast` 是把这层控制拿出来单独做。

### 2. 不用来回切“自动连播”和“播完暂停”

这是原生体验里很烦的一点。看视频时一套逻辑，听内容时又是另一套逻辑，经常要切来切去。

`Bilicast` 直接提供：

- 单曲循环
- 列表循环
- 全部循环
- 随机播放

听内容时按播放器的规则来，不用迁就视频页逻辑。

### 3. 不需要先建收藏夹

看到一个视频，点一下就能进自己的播放列表。

这和收藏夹是两套用途：

- 收藏夹偏长期整理
- `Bilicast` 偏即时加入、即时播放

如果你只是想“这个我等会听”，没必要先走一遍收藏夹流程。

## 还有哪些差异化

除了上面三点，这个项目还有几处比较实用：

### 多分类，而不是一个大队列

可以按场景分开管理，比如：

- 工作 BGM
- 学习内容
- 深夜电台
- Live
- 临时想听

### 视频页直接加入，操作链路短

扩展会在 B 站视频页提供加入入口，不需要先切到别的页面再操作。

### 后台播放独立运行

播放不绑在当前标签页上。你可以继续看别的视频，或者切到别的页面，不用一直守着同一个播放器界面。

### 按 `BV + P` 记录视频项

多 P 视频不是粗略算成一条，而是按具体分 P 加入。拿来收集合集、课程、分章节内容会更顺手。

## 功能

- 视频页一键加入播放列表
- 自定义分类创建 / 删除
- 后台播放 B 站音频流
- 播放 / 暂停 / 上一首 / 下一首
- 单曲循环 / 列表循环 / 全部循环 / 随机播放
- 进度拖动
- 独立音量控制
- 当前播放高亮
- 批量删除列表项
- 自动解析视频音频地址
- 支持多 P 视频按页加入

## 适合谁

- 把 B 站当歌库的人
- 经常听 Live、翻唱、播客、长视频的人
- 想边工作边听 B 站的人
- 不想维护收藏夹，只想快速加入和播放的人
- 觉得原生 list 在“听”这件事上不够顺手的人

## 技术实现

项目基于 Chrome Manifest V3，主要分成四层：

- `content script`
 负责注入 B 站视频页，读取当前视频信息，并提供“一键加入播放列表”的入口
- `background service worker`
 负责维护播放列表、分类、播放状态和消息路由
- `offscreen document`
 负责实际音频播放，让播放独立于当前标签页
- `popup UI`
 负责列表管理和播放器控制

当前实现里用到了：

- `chrome.storage.local` 持久化播放列表和状态
- `offscreen document` 做后台音频播放
- B 站接口解析视频 `cid` 和音频流地址
- `declarativeNetRequest` 处理音频请求头

## 安装

### 本地构建

```bash
pnpm install
pnpm build
```

构建产物会输出到 `dist/`。

### 加载扩展

1. 打开 `chrome://extensions/`
2. 开启开发者模式
3. 选择“加载已解压的扩展程序”
4. 选择项目里的 `dist/` 目录

## 开发

```bash
pnpm build
```

当前构建脚本会把 `manifest.json`、`src/` 和 `icons/` 复制到 `dist/`，适合快速迭代扩展逻辑。
